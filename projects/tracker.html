项目 · 求职系统

我正在用它找工作的一套系统

岗位库、投递日志、状态回写、跟进节奏、复盘归档，全部在一张飞书多维表格里跑。投递出去的那一秒，状态自己就更新了。

50+ 岗位入库2 张表联动7 天投出100% API 读写

它解决什么

收藏夹里的岗位越存越多，投递记录只在本子上，状态全靠脑子记。投完就忘、忘了就漏、漏了就错投。

怎么跑起来的

两张表：一张岗位追踪表（公司、岗位、薪资、匹配度、状态），一张投递日志表（日期、公司、岗位、事件、详情、结论），用 API 打通。

  • 投递 / HR 回复 / 约面 / 一面 / 二面 / Offer / 拒绝 / 跟进 八种事件流
  • 关闭的岗位自动标出，不再浪费投递机会
  • 按匹配度、地点、薪资三重分档，决定先投谁
  • 投递按简历标准计 EXP，每晚生成一次结算卡
  • 零手工同步：不维护第二份台账

我的做法

  • 梳理流程：把「投了什么」拆成可记录的事件字段
  • 用 lark-cli 全 API 读写，不手工填表
  • 状态回写：投递即更新，关闭自动标出
  • 复盘口径固定：投递数、跟进节奏、EXP 结算

边界说明

这系统里的每一条记录都是我的真实投递数据，属于私人求职信息。所以公开版本不放任何记录截图——只公开结构与机制。
